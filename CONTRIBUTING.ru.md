# Как участвовать

[English](CONTRIBUTING.md) · [Oʻzbekcha](CONTRIBUTING.uz.md) · **Русский**

Спасибо за помощь. Issue, pull request и исправления переводов — всё
приветствуется.

## Рабочий процесс

1. Отдельная ветка на задачу: `feature/login`, `fix/payment-error`.
2. Формат коммитов: `feat: add login`, `fix: validate phone number`.
   Частые типы: `feat`, `fix`, `docs`, `chore`, `refactor`, `test`, `ci`.
3. Pull request — небольшой и по одной теме.
4. Перед открытием PR выполните проверки:

   ```bash
   make lint && make test && make build && make doctor
   ```

5. Значимые технические решения фиксируйте как ADR в `docs/adr/`.

## Что проверяет CI

| Задача | Что проверяет |
| --- | --- |
| `structure` | Ссылки в документации, соответствие `.env.example`, гигиену секретов, корректность YAML |
| `node` | Запускается только при наличии `package.json`: install, lint, test, build |
| `python` | Запускается только при наличии `pyproject.toml`: install, lint, test |
| `ci-ok` | Агрегирует остальные — именно её делайте обязательной проверкой |

Пропуск задачи `node`/`python` при отсутствии стека — это нормально, а не сбой.

## Добавление языка

Сообщения скриптов лежат в `scripts/lang/`. Чтобы добавить язык:

1. Скопируйте `scripts/lang/en.sh` в `scripts/lang/<код>.sh`.
2. Переведите значения. Сохраните **все ключи**, а также **количество и порядок
   подстановок `%s`** — это строки формата printf.
3. Проверьте: `STARTER_LANG=<код> make doctor` и `STARTER_LANG=<код> make lint`.
4. Добавьте язык в списки `STARTER_LANG` в `README*.md` и `scripts/README.md`.

Совпадение ключей проверяется одной командой:

```bash
diff <(grep -o '^T_[A-Z_]*' scripts/lang/en.sh | sort) \
     <(grep -o '^T_[A-Z_]*' scripts/lang/<код>.sh | sort)
```

> Примечание: в bash внутри одинарных кавычек нельзя экранировать `'`. Если
> вашему языку нужны апострофы, используйте корректные символы Unicode — в
> узбекском каталоге это `oʻ`, `gʻ` (U+02BB) и `ʼ` (U+02BC).

## Изменение скриптов

- Весь текст, который видит пользователь, берётся из каталога сообщений —
  никаких строк прямо в коде.
- Совместимость с **bash 3.2** (версия по умолчанию в macOS): без ассоциативных
  массивов и без `mapfile`.
- Не прописывайте путь к конкретному приложению или сервису. Автоматика
  основана на обнаружении, поэтому любой каталог можно удалить.
- Проверки в `doctor.sh` должны сообщать о проблеме *и* о способе её
  исправления.

## Перевод документации

Справочная документация ведётся на английском. Переводятся три документа:
`README`, `docs/guides/01-getting-started.md` и `CONTRIBUTING.md`. Если вы меняете
один из них, обновите версии на других языках или отметьте в PR, что они ещё
требуют обновления.

## Сообщения о проблемах

- Ошибки и предложения: используйте шаблоны issue.
- Безопасность: **не** открывайте публичный issue — см.
  [SECURITY.md](SECURITY.md).
